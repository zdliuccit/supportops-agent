## ADDED Requirements

### Requirement: 租户级知识源与文档
平台 SHALL 为知识源和知识文档保存稳定标识、租户、负责人、来源类型、环境、受众、状态、更新时间和更新频率，并在所有管理与读取路径实施租户隔离。

#### Scenario: 创建知识文档
- **WHEN** 当前租户的知识管理员在授权知识源下创建文档
- **THEN** 平台创建租户级稳定文档身份和初始草稿版本，并记录创建审计事件

#### Scenario: 跨租户读取文档
- **WHEN** 主体尝试读取其他租户的知识文档或版本
- **THEN** 平台拒绝访问且不泄露资源是否存在

### Requirement: 不可变知识版本
平台 SHALL 将标题、Markdown 正文、内容哈希、章节锚点、变更说明和创建者保存为不可变知识版本。已发布版本 MUST NOT 被原地修改。

#### Scenario: 更新已发布内容
- **WHEN** 知识管理员修改已经发布的文档内容
- **THEN** 平台创建新的草稿版本并保留原发布版本和历史引用

#### Scenario: 重复保存相同内容
- **WHEN** 新版本内容与当前草稿或发布版本的规范化内容哈希相同
- **THEN** 平台拒绝无变化版本或返回现有版本，不生成重复历史

### Requirement: 审核与发布状态机
平台 SHALL 通过服务端状态机控制草稿、审核中、已发布、已取代、已失效和已归档状态。发布、失效和回滚 SHALL 在事务中执行，并验证调用者权限和期望修订号。

#### Scenario: 发布已审核版本
- **WHEN** 授权知识管理员发布处于审核中且字段完整的版本
- **THEN** 平台原子地将其设为当前发布版本、取代旧版本、生成快照并记录审计

#### Scenario: 并发发布冲突
- **WHEN** 两个请求基于同一旧修订号并发发布不同版本
- **THEN** 平台仅允许一个请求成功，另一个返回可识别的并发冲突

#### Scenario: 回滚历史版本
- **WHEN** 授权知识管理员选择历史已发布版本执行回滚
- **THEN** 平台从该快照创建新的审核/发布版本，不修改原历史记录

### Requirement: ACL 与有效期
平台 SHALL 仅向租户匹配、权限允许且命中角色、组织单元或主体允许范围的用户提供知识内容。版本必须已发布，并位于 `effective_from` 与 `effective_until` 定义的有效期内；规则不完整时 SHALL 默认拒绝。

#### Scenario: 允许的组织成员访问
- **WHEN** 当前主体属于文档允许的组织范围且版本已发布并有效
- **THEN** 平台返回稳定文档 ID、版本、标题、章节和内容快照

#### Scenario: 文档已过期
- **WHEN** 已发布版本超过有效期
- **THEN** 平台不再把该版本作为有效知识返回，并将文档标记为过期或待复核

#### Scenario: 平台管理员没有业务受众权限
- **WHEN** 平台管理员仅具有配置权限但未命中文档业务 ACL
- **THEN** 平台允许查看治理元数据但拒绝读取受限正文

### Requirement: 可追溯检索快照
每次发布 SHALL 生成不可变知识快照，至少包含租户、文档、版本、内容哈希、标题、章节锚点、ACL 摘要、有效期和发布时间。后续检索能力 MUST 只消费当前有效且权限允许的已发布快照。

#### Scenario: 取得检索候选快照
- **WHEN** 内部检索调用提供可信租户和主体上下文
- **THEN** 平台只返回该主体可访问的当前有效已发布快照及稳定引用字段

#### Scenario: 草稿不能进入检索
- **WHEN** 文档存在更新后的草稿但尚未发布
- **THEN** 平台继续返回原有效发布快照且不暴露草稿内容

### Requirement: 发布事件与索引一致性
平台 SHALL 为发布、取代、失效和归档写入持久化、可幂等消费的事件，以便后续索引器更新检索状态。事件处理失败 MUST NOT 改写已经提交的知识事实。

#### Scenario: 发布事件重复消费
- **WHEN** 索引消费者使用同一事件 ID 重复处理知识发布事件
- **THEN** 最终索引状态保持一致且不产生重复版本

#### Scenario: 索引更新暂时失败
- **WHEN** 发布事务成功但后续索引处理失败
- **THEN** 平台保留待处理事件和失败状态供重试，并且不把未索引内容伪装为可检索

### Requirement: 知识管理 API 与界面
平台 SHALL 提供分页、筛选和统一错误契约的知识源、文档、版本、审核、发布、失效、回滚和审计管理 API，并提供最小管理界面覆盖对应流程。

#### Scenario: 查看知识清单
- **WHEN** 知识管理员按来源、状态、负责人或过期状态筛选列表
- **THEN** 平台返回当前租户内确定排序的分页结果和总数

#### Scenario: 发布前确认
- **WHEN** 知识管理员在界面发起发布、失效或回滚
- **THEN** 界面明确展示目标文档、版本和影响，并在用户确认后提交一次操作

#### Scenario: 空数据或服务异常
- **WHEN** 当前租户没有知识或管理 API 暂时不可用
- **THEN** 界面展示可理解的空状态或错误恢复操作，不显示伪造数据

### Requirement: 审计与敏感内容保护
平台 SHALL 记录知识创建、修改、提交审核、发布、失效、回滚、ACL 变更和访问拒绝事件。审计记录 SHALL 可关联主体、租户、文档、版本、动作、结果、时间和追踪 ID，且不得保存完整敏感正文、密钥、令牌或隐藏推理。

#### Scenario: ACL 变更审计
- **WHEN** 授权管理员修改文档受众或组织范围
- **THEN** 平台记录修改前后摘要、操作者、修订号和追踪 ID

#### Scenario: 审计员查询记录
- **WHEN** 授权审计员查询知识生命周期事件
- **THEN** 平台提供只读分页记录，并禁止其通过审计接口修改知识或读取无权正文

### Requirement: Mock 与生产知识隔离
平台 SHALL 标记知识来源环境，并在企业试运行和生产发布路径拒绝把 `mock` 来源误作为正式知识。导入 P0 候选清单 SHALL 是显式、可重复且租户限定的操作。

#### Scenario: 向生产发布 Mock 知识
- **WHEN** 管理员尝试在 production 环境发布来源标记为 `mock` 的版本
- **THEN** 平台拒绝发布并返回可审计的校验错误

#### Scenario: 重复导入 P0 候选清单
- **WHEN** 同一租户重复执行相同版本的候选知识导入
- **THEN** 平台通过稳定外部 ID 或幂等键避免创建重复文档
