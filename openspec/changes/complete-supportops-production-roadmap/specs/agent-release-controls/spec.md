## ADDED Requirements

### Requirement: 完整版本清单与评测门禁
发布 SHALL 固定 Agent/Prompt、模型/路由、知识/检索、工具/连接器、权限/审批、图结构、评测集版本，并通过适用功能与安全回归。

#### Scenario: 策略或知识变更
- **WHEN** 新版本修改权限、检索或工具描述
- **THEN** 触发对应回归与版本记录，不能只测模型连通性

#### Scenario: 未记录的历史与服务器发布清单
- **WHEN** 读取发布版本的清单或比较两个固定版本
- **THEN** 新清单由服务器在发布事务中保存版本/源码/Schema/策略摘要，旧记录不按当前代码补造；损坏清单隐藏且拒绝激活。比较保留未知状态，只返回同租户/同 Agent 的摘要/版本标识，不返回秘密或正文，不视为评测批准

#### Scenario: 运行知识与凭据边界
- **WHEN** 新版本固定检索策略或记录发布时凭据 revision
- **THEN** 当前知识 ACL/有效快照与实际证据仍在每次检索定位，本轮凭据 revision 在 Run 创建时固定；清单不冻结整个知识语料或成为执行授权，尚无评测结果时明确 not_assessed

#### Scenario: 安全门禁失败
- **WHEN** 发现跨租户访问或高风险审批绕过
- **THEN** 阻止发布，不允许降低风险或关闭校验豁免

#### Scenario: 当前范围改变或结果过期
- **WHEN** 最新追加评测与固定清单、当前源码/模型请求/工具/凭据、人员/项目授权或知识快照/ACL/索引/自然有效期不符，报告损坏或超过服务器有效期
- **THEN** 正式激活和正式新会话拒绝，不选更旧通过记录、不手工覆写 passed；只读门禁保留 failed/missing/stale 和原始实测缺失，范围超限拒绝而非截断放行

#### Scenario: 暂缓评测与开发激活
- **WHEN** W19执行器或批准数据集/负载/可信执行器/费用上限未接通
- **THEN** staging/production无开关可跳过门禁，local/dev/test仅可明确标记未验收的开发激活，已知安全/功能/完整性失败仍拒绝；不生成通过结果，不把服务器清单当作实测证据

#### Scenario: 显式检查后激活
- **WHEN** 管理员从管理台保存新的候选版本
- **THEN** 默认不激活，可查看门禁、实测阈值和服务器分页评测元数据历史再显式操作；提交时在Agent锁内重新检查固定引用和当前门禁。旧activate=true原子接口失败整体回滚，拒绝单独追加最小审计且不引用未落库版本

### Requirement: 灰度与回滚保留历史
灰度 SHALL 指定租户/主体/流量范围并观察质量成本；回滚 SHALL 停止新激活并保留旧会话、审批与在途动作的版本及对账事实。

#### Scenario: 灰度新版本
- **WHEN** 部分主体被纳入试运行
- **THEN** 新会话选中指定版本，既有会话不被原地升级

#### Scenario: 固定范围与稳定选版
- **WHEN** 管理员保存并显式启动灰度，获准主体创建新会话
- **THEN** 固定租户/Agent/两版本/主体/不可变策略摘要，主体哈希分组稳定；初始最多10%、扩量步进最多10个百分点、最高90%保留基线。只在两版本完整passed、服务器批准策略和巡检有效时分配候选；不使用开发豁免、不自动授予权限、不改变旧会话版本和分组，全量须另经显式激活

#### Scenario: 缺失观测与受控扩大
- **WHEN** 管理员请求扩大或Worker巡检当前灰度
- **THEN** 只读取本轮新会话的有界元数据，检查观察时长、两组足量样本、无等待/取消、完整费用/耗时、结构化结果绑定及绝对/相对阈值；缺失不填零，超限不截断放行，客户端上报不批准扩量。授权拒绝或已知失败、门禁/策略/基线变化及观察期满缺失触发系统暂停，巡检过期关闭新增候选流量，不自动扩大或推断业务成功/客户端SLO

#### Scenario: 显式停止和激活切换
- **WHEN** 管理员提交带当前修订的暂停/恢复/停止/扩大，或激活某个版本
- **THEN** Agent锁串行控制和新会话选版，每次启动/恢复/扩大新增观察轮次；状态事件追加且区分人工/系统，停止不可复活。停止曾启动灰度或激活其他版本时永久撤回该候选新写许可；提升该候选则关闭灰度但不撤回它。旧会话、审批、已发生或未知动作和回执保留，继续当前授权下的只读对账

#### Scenario: 回滚在途动作
- **WHEN** 发布回滚时存在待审批或未知动作
- **THEN** 按冻结版本重新检查授权/对账，不删除记录或重放副作用

#### Scenario: 回滚与迟到 Mock 提交竞争
- **WHEN** 管理员切换到较旧版本，退出版本仍有未发出动作或旧执行者准备提交隔离Mock目标
- **THEN** 退出版本追加不可解除的撤回事实并禁止新激活/新写动作，提案与执行来源均须未撤回；目标事务与回滚按版本锁串行，先提交的副作用保留并对账，后提交的拒绝。已消费或未知结果不改参数/业务键、不清回执；真实外部系统需独立契约，不能继承Mock原子保证
