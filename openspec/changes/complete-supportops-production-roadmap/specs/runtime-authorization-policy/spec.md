## ADDED Requirements

### Requirement: 调用时可信身份与资源范围
平台 MUST 在 Run 领取及每次工具调用前校验当前用户、租户、Agent grant 和资源权限；历史角色快照只用于追踪，不得扩权。

#### Scenario: 排队后撤销
- **WHEN** 用户或 Agent grant 在排队期间被停用
- **THEN** 执行被拒绝且记录稳定授权原因，无越权外部调用

#### Scenario: 模型替换资源
- **WHEN** 模型参数指向主体无权访问的用户、项目或工单
- **THEN** 服务端拒绝或按可信范围收窄，并记录授权决定

### Requirement: 目录策略与风险规范一致
平台 SHALL 从统一受控策略解析工具启停、版本、所需角色与 R0–R4 风险；旧风险值 SHALL 按明确保守规则兼容，不能用配置或 Prompt 降级高风险。

#### Scenario: 停用历史工具
- **WHEN** 管理员停用已发布 Agent 所引用工具
- **THEN** 新旧版本后续调用均拒绝，目录变更可审计

#### Scenario: 参数提高风险
- **WHEN** 同一工具从单项查询变成敏感导出或批量变更
- **THEN** 重新计算风险并进入对应授权及审批规则，不能沿用低风险结论

### Requirement: 额度与安全拒绝
平台 SHALL 原子执行单工具 max_calls_per_run、工具总量、并发与租户配额；审批未接通的高风险动作 MUST 保持拒绝。

#### Scenario: 并行超过单工具限额
- **WHEN** 两个并行调用竞争最后一次额度
- **THEN** 至多一个获得许可，计数与拒绝原因可追踪

#### Scenario: 只有审批配置字段
- **WHEN** 高风险工具配置 required 但无有效审批记录
- **THEN** 不执行工具，不把配置声明当作审批凭证
