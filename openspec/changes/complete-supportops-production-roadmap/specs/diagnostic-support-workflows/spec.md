## ADDED Requirements

### Requirement: 429 单领域显式编排
平台 SHALL 按场景基线执行分类、信息补齐、受控查询、知识规则、证据判断与回答/升级；产品 P0 默认单 Agent 与隔离 Mock。

#### Scenario: 可确认的限流
- **WHEN** 有效请求 ID、配额/日志与规则共同确认 429 原因
- **THEN** 回答给出已确认原因、查询时间、规则引用和适用建议

#### Scenario: 无法唯一定位
- **WHEN** 缺少请求 ID 或证据矛盾
- **THEN** 追问必要信息或升级，明确哪些事实尚未确认

### Requirement: 受控只读诊断工具
平台 SHALL 提供 4–6 个必要的只读能力，限制用户/项目/时间/字段范围，覆盖日志、配额/账户摘要、路由状态与故障事件；真实接入先通过契约和权限测试。

#### Scenario: 查询其他用户日志
- **WHEN** 模型工具参数越过当前主体资源范围
- **THEN** 拒绝且不返回原始 Prompt、密钥或其他用户资料

#### Scenario: 关键依赖失败
- **WHEN** 日志或故障查询超时
- **THEN** 安全降级并保留已完成排查，不伪造工具结果或重复无限调用

### Requirement: 流程有界与可接管
诊断 SHALL 有步骤/重试/预算上限和阶段事件，升级包 SHALL 包含已确认事实、未确认事项、排查步骤和证据。

#### Scenario: 超过排查上限
- **WHEN** 诊断循环达到步骤或预算上限
- **THEN** 进入可解释升级路径，客服无需重做已完成基础查询

### Requirement: 隔离诊断的固定事实工作流
Mock 429 SHALL 使用 `mock_429_workflow_v1`，固定十节点、最多四项业务查询与一次关键词检索；只有唯一跨源一致候选和当前获准的 `supportops_429_rule_v1:<code>` 声明共同支持时才标记 confirmed_mock。声明只关联平台预定义规则，不能执行知识正文的代码或扩权指令。

#### Scenario: 模拟恢复与授权变化
- **WHEN** 同一 Run 创建新的安全执行尝试
- **THEN** 仅可复用同参数/实现/当前目录策略、五分钟内成功的只读事实，预算消费保留，知识由新尝试重新检索；刷新只读取已有阶段和结果，不创建新 Run

#### Scenario: 查看旧诊断来源
- **WHEN** 主体展开报告，而知识引用或工具授权已失效
- **THEN** 隐藏事实、根因候选与接管包，保留失效提示；模型调用和 checkpoint 不因固定工作流而被伪造
