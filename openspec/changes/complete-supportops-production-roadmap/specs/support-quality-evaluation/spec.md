## ADDED Requirements

### Requirement: 版本化固定评测集
平台 SHALL 复用 S01–S20 场景，每场景至少正例、边界例、失败/升级例，保存样本/参考事实/允许禁止工具/风险/升级条件和完整版本清单；企业试运行先复核脱敏真实场景。

#### Scenario: 创建 P0 基线
- **WHEN** 准备 API 支持 Mock 发布候选
- **THEN** 至少 60 个固定样本覆盖四条主路径，内部基线不冒充企业真实验收

### Requirement: 业务结果与安全硬门禁
评测 SHALL 检查事实/引用、路由、参数、升级包、真实业务最终状态、成本与延迟；跨租户、R4 绕过和严重泄露 MUST 阻断发布，初始阈值沿用批准基线。

#### Scenario: 回答声称成功
- **WHEN** 模型声称工单已建但目标系统无记录
- **THEN** 业务结果评分失败，不能按文本相似度判定成功

#### Scenario: 指标未达标
- **WHEN** 质量或性能指标低于批准基线
- **THEN** 记录差距/根因/责任人与处置；安全指标不能例外放行

#### Scenario: 沿用内部批准目标
- **WHEN** 记录 W19 的目标与适用范围
- **THEN** 沿用 0.1.0 / 2026-09-14 的 P0 内部批准与主规格阈值，明确公式、样本/负载/时钟来源及 P1 企业外部复核边界；目标记录不作为达标结果，未批准成本上限保留缺失

#### Scenario: 调整非安全目标
- **WHEN** 团队提出改变目标或适用范围
- **THEN** 记录版本、实际差距、根因、补救、责任人和到期日并取得产品与技术/工程负责人共同批准，保留旧基线；跨租户、审批绕过、严重泄露等安全硬门禁不适用豁免

### Requirement: 基础设施故障与条件线上反馈
发布范围 SHALL 有真实隔离 PostgreSQL/Redis、多 Worker、断流/恢复、权限撤销与 Prompt Injection 验收；在线采样/评测仅在用户数据治理与成本门禁批准后启用。

#### Scenario: 进程故障演练
- **WHEN** 在执行/通知/提交边界使 Worker 或依赖失败
- **THEN** 按对应场景验证收敛、无重复副作用和无越权，而非仅跑 SQLite 替身

#### Scenario: 线上样本包含敏感数据
- **WHEN** 采样拟传输租户正文到评测系统
- **THEN** 按批准作用域脱敏或拒绝，不能默认上传全部会话
