## ADDED Requirements

### Requirement: 上下文来源与裁剪
平台 SHALL 分离完整历史和模型输入，保存已确认事实、证据来源时间、冲突与未完成事项；裁剪 SHALL 保留本轮输入并隔离不可信内容与指令。

#### Scenario: 对话超过窗口
- **WHEN** 历史与工具结果达到模型输入上限
- **THEN** 按明确策略摘要/裁剪并保留关键证据，不能无限追加或删掉当前问题

#### Scenario: 不可信工具指令
- **WHEN** 日志或知识正文包含让模型扩权的文本
- **THEN** 文本作为受限数据处理，不修改系统指令、主体或可用工具范围

### Requirement: 完整 Token 与累计费用
平台 SHALL 在每次模型调用前计量完整输入与输出预留，并计入重试、路由和工具预算；提供 Run 和租户累计计量，不把未知定价当作零。

#### Scenario: 多次调用耗尽预算
- **WHEN** 一次 Run 多次模型调用将超过累计预算
- **THEN** 后续调用被阻止并返回可解释退出或升级结果

#### Scenario: 未知定价硬预算
- **WHEN** 启用费用硬上限但选中模型无可信定价
- **THEN** 拒绝该调用或按预先批准的保守规则处理，不静默绕过

### Requirement: 预算预留与恢复
平台 SHALL 协调并行预留、真实 usage 结算和失败/取消释放，恢复 attempt 不得重复计费或重置已消耗额度。

#### Scenario: 恢复同一 Run
- **WHEN** Worker 在计量提交后重启
- **THEN** 保留已消耗与预留事实，恢复只结算本次新增真实调用

#### Scenario: 并发租户额度
- **WHEN** 多个会话竞争租户余额
- **THEN** 原子预留避免透支，缺失 usage 标记 unknown 并按策略保守结算
