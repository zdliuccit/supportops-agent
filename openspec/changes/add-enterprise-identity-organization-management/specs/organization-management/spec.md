## ADDED Requirements

### Requirement: 公司资料管理
平台管理员 SHALL 查看和更新当前租户公司的名称、简称、Logo、联系邮箱和状态信息，接口 MUST 从可信身份推导租户。

#### Scenario: 更新公司资料
- **WHEN** 管理员提交有效公司名称和可选展示资料
- **THEN** 系统只更新当前租户并返回最新资料

### Requirement: 组织树查询
系统 SHALL 返回当前租户按名称稳定排序的树形部门结构，并同时包含每个部门的直接用户数量和包含全部后代部门的用户总数量。

#### Scenario: 查询多层组织
- **WHEN** 当前租户存在多级部门节点
- **THEN** API 返回正确父子关系且不包含其他租户节点

#### Scenario: 统计部门及子部门人数
- **WHEN** 某部门及其子部门分别关联用户
- **THEN** API 的 `direct_user_count` 仅统计当前部门，`user_count` 统计当前部门及全部后代部门用户总数

### Requirement: 组织单元生命周期
平台管理员 SHALL 仅使用名称和上级部门创建、编辑部门；接口与数据库 MUST NOT 继续维护部门代码、类型、人工排序或状态，并且系统 MUST 阻止跨租户父节点、自引用和循环结构。

#### Scenario: 创建子部门
- **WHEN** 管理员在当前租户有效父节点下创建部门
- **THEN** 系统保存节点并在组织树对应位置返回

#### Scenario: 将节点移动到后代
- **WHEN** 管理员尝试把组织节点的父节点改为其后代
- **THEN** 系统返回校验错误且组织树不变

### Requirement: 安全删除组织单元
系统 SHALL 只允许删除没有子节点且没有用户引用的部门，MUST NOT 级联删除用户或下级部门。

#### Scenario: 删除空部门
- **WHEN** 管理员删除无子节点且无用户的部门
- **THEN** 系统删除该节点并返回成功

#### Scenario: 删除使用中的部门
- **WHEN** 部门包含子节点或关联用户
- **THEN** 系统返回冲突错误并保留完整数据

#### Scenario: 管理员从部门树发起删除
- **WHEN** 管理员查看部门树中的部门操作
- **THEN** 编辑和删除入口默认隐藏且在悬浮对应部门行时以无间隙图标组显示，部门人数大于零或存在下级部门时删除入口禁用并明确提示不能删除，否则确认后执行删除

### Requirement: 统一树形部门选择
Web 应用 SHALL 在部门管理和用户管理表单中复用统一树形部门选择器，下拉默认最多展示四级部门，选中后 SHALL 展示从顶级部门到末级部门的完整路径，但提交与数据库持久化 MUST 仅使用所选末级部门 UUID。

#### Scenario: 回显已有部门归属
- **WHEN** 表单向部门选择器传入已有部门 UUID
- **THEN** 选择器默认选中对应节点并展示其完整层级路径

#### Scenario: 选择多级部门
- **WHEN** 管理员从四级以内的树形选项中选择一个部门
- **THEN** 输入区域展示多级部门路径且表单值仅为所选部门 UUID

### Requirement: 全局部门状态与路径解析
Web 应用 SHALL 使用 Redux Toolkit 集中保存当前租户的部门树。进入部门管理页面时 MUST 重新请求部门接口并在全局状态更新完成后结束页面 Loading；部门创建、编辑和删除后 MUST 再次刷新全局部门树。树形选择器、用户列表和顶部身份信息 SHALL 从同一全局状态读取部门数据。

#### Scenario: 进入部门管理页面
- **WHEN** 管理员导航到部门管理页面
- **THEN** 页面进入 Loading、请求最新部门树、更新 Redux 状态，然后再展示部门内容

#### Scenario: 部门发生变更
- **WHEN** 管理员成功创建、编辑或删除部门
- **THEN** Web 应用等待全局部门树刷新完成后结束操作状态

#### Scenario: 根据部门 ID 展示层级路径
- **WHEN** 用户列表、树形选择器或顶部身份区域获得末级部门 UUID
- **THEN** 统一路径解析方法返回最多四级的部门名称数组，界面按完整路径展示
