## ADDED Requirements

### Requirement: 独立登录页面
Web 应用 SHALL 在 `/login` 提供响应式双栏登录页，使用项目自有品牌和图形，包含邮箱、密码可见性、提交中、错误和键盘提交状态，且 MUST NOT 显示 MUI Store 顶部框架。

#### Scenario: 桌面端打开登录页
- **WHEN** 未认证用户在桌面视口访问 `/login`
- **THEN** 页面展示介绍区与登录表单区，视觉层级、间距和圆角符合统一后台设计语言

#### Scenario: 移动端打开登录页
- **WHEN** 未认证用户在窄屏访问 `/login`
- **THEN** 页面隐藏非必要介绍图形并完整呈现可操作表单

#### Scenario: 登录失败
- **WHEN** 登录接口返回认证错误
- **THEN** 页面保留邮箱、清空或保留可安全重试状态并播报明确错误

### Requirement: 认证路由守卫
Web 应用 SHALL 在渲染业务页面前验证本地令牌，未认证或令牌失效时跳转 `/login`，登录成功后返回原目标路由。

#### Scenario: 未登录访问管理页
- **WHEN** 用户直接打开 `/admin/users`
- **THEN** 页面不闪现受保护内容并跳转登录页

#### Scenario: 已登录刷新聊天页
- **WHEN** 用户在具体 Agent 会话路由刷新
- **THEN** 守卫验证完成后直接恢复目标页面，不闪现登录或其他业务页面

#### Scenario: 登录成功进入业务页面
- **WHEN** 用户完成邮箱密码登录并首次进入受保护路由
- **THEN** 页面使用平台全局 Loading 承接路由切换，并至少展示 300ms 后再呈现业务内容

### Requirement: 企业后台壳层
登录后的 Web 应用 SHALL 使用分组左侧导航、顶部身份工具栏和圆角主内容区，并在桌面与移动视口保持可用；管理入口 SHALL 根据服务端角色展示。

#### Scenario: 平台管理员进入后台
- **WHEN** 平台管理员登录成功
- **THEN** 侧栏展示工作台、Agent、模型、用户、部门和公司信息入口，右侧顶部以固定 72px 高度展示面包屑和当前用户信息

#### Scenario: 普通员工进入后台
- **WHEN** 普通员工登录成功
- **THEN** 侧栏只展示有权访问的员工功能且后端继续实施授权

### Requirement: 安全退出
Web 应用 SHALL 提供退出操作，清除本地令牌和身份缓存后跳转登录页。

#### Scenario: 用户退出登录
- **WHEN** 用户从顶部身份菜单选择退出
- **THEN** 受保护页面立即不可访问且浏览器返回登录页

### Requirement: 统一组件体系
Web 应用 SHALL 使用本地 shadcn UI 组件作为交互控件基础，页面 MUST NOT 直接使用浏览器原生 select 或 checkbox，并应优先使用统一的 Button、Alert、Sheet、Tooltip 等组件表达对应交互和状态。

#### Scenario: 管理员使用表单控件
- **WHEN** 管理员打开新增、编辑或筛选表单
- **THEN** 选择器、复选框、按钮、焦点和禁用状态使用一致的设计令牌与键盘交互

#### Scenario: 弹窗内打开选择器
- **WHEN** 用户在 Dialog 或其他浮层中打开普通选择器或树形部门选择器
- **THEN** 选择内容层使用不透明背景、边框、阴影和高于弹窗内容的层级，不与后方表单文字重叠

#### Scenario: 管理页面展示数据列表
- **WHEN** 管理页面需要以表格展示结构化数据
- **THEN** 页面通过统一表格组件传入列定义、数据源和行唯一键，表格使用统一表头视觉、自适应内容行高和可选客户端分页；分页启用时支持选择每页条数、点击页码和输入指定页码跳转，每页条数选项由组件内部统一维护

#### Scenario: 管理页面列表没有数据
- **WHEN** 统一表格接收到空数据源
- **THEN** 表格保留表头并在表体统一显示空数据提示，同时隐藏无意义的分页控件

#### Scenario: 用户列表展示标题栏
- **WHEN** 管理员查看企业成员列表
- **THEN** 列表标题栏仅展示“企业成员”标题和刷新操作，不重复展示账号总数，列表外层不使用阴影

### Requirement: 统一列表接口分页
所有普通扁平列表 GET 接口 SHALL 接受从 1 开始的 `page` 和 `page_size`，其中 `page_size` 默认 20 且最大 100；响应 SHALL 返回 `items`、`total`、`page`、`page_size` 和 `pages`。数据和总数查询 MUST 使用相同的租户、权限与业务过滤条件，并在数据库层分页。完整树结构与流式响应 MAY 因完整性或协议语义不分页，但必须明确说明。

#### Scenario: 查询普通列表的后续页
- **WHEN** 客户端使用有效的 `page` 和 `page_size` 查询普通扁平列表
- **THEN** 服务端按确定性顺序返回对应页数据和准确分页元数据，不跨租户或权限边界统计

#### Scenario: 查询超过总页数的页码
- **WHEN** 客户端请求的页码超过当前过滤结果总页数
- **THEN** 服务端返回空 `items`、请求页码和准确总数，不返回 404

#### Scenario: 查询完整组织树
- **WHEN** 客户端读取树形部门结构
- **THEN** 服务端一次返回完整层级，不对树节点应用普通扁平列表分页

### Requirement: 弹窗表单必填标记
新增、编辑、重命名和配置类弹窗 SHALL 使用统一表单字段组件承载校验状态；表单不得依赖浏览器原生 `required` 约束，而应在提交时执行业务校验并将错误显示在对应字段下方；必填字段需在 Label 文案前显示红色 `*`，非必填字段不得显示必填标记。

#### Scenario: 提交缺少必填字段
- **WHEN** 用户提交缺少必填值的弹窗表单
- **THEN** 表单阻止提交，并在对应字段下方显示错误提示；错误字段边框呈红色，正常字段不预留错误空白

#### Scenario: 查看必填字段
- **WHEN** 用户打开包含必填字段的弹窗
- **THEN** 必填字段以 Label 文案前的红色 `*` 明确标识

### Requirement: 统一操作反馈
Web 应用 SHALL 通过全局 Toast 展示增删改、启停、发布、测试和会话管理等操作结果；成功、失败和警告 MUST 分别使用绿色、红色和黄色视觉状态。页面加载失败、字段校验以及需要持续解释的只读或禁用状态 SHALL 保留在页面上下文中展示。

#### Scenario: 操作成功
- **WHEN** 用户完成创建、保存、删除、启用或其他成功操作
- **THEN** 页面在全局固定位置展示绿色成功 Toast，且不再重复渲染页面级成功 Alert

#### Scenario: 操作失败
- **WHEN** 操作接口返回错误或客户端操作抛出异常
- **THEN** 页面展示红色失败 Toast，并优先呈现可安全展示的服务端错误信息

#### Scenario: 操作需要注意
- **WHEN** 操作完成后会进入停用状态、测试未通过或发生可恢复的并发冲突
- **THEN** 页面展示黄色警告 Toast，并在适用时提供恢复操作入口
