## Context

当前 API 用 JWT 表示可信身份，但 Web 会自动调用开发令牌接口，`users` 仅保存外部 subject、显示名和角色，不具备本地密码登录、公司资料或组织层级。现有 Web 已有 Agent 目录、聊天、Agent 管理和模型管理页面，但各页面自行包裹顶部导航，缺少统一登录保护与企业后台布局。

参考站点的 Live Preview 已实际检查。实现只提取双栏登录、固定侧栏、顶部工具栏、圆角卡片、浅色背景、深色按钮和绿色强调色等设计规律，使用 SupportOps 自有品牌与 CSS 图形，不复制商业模板代码、Logo 或插画。

## Goals / Non-Goals

**Goals:**

- 使用本地邮箱密码认证真实用户，并保持现有 JWT 租户与角色授权模型。
- 支持单租户公司的资料、树形组织架构和用户生命周期管理。
- 安全引导默认管理员，密码仅以带随机盐的 scrypt 哈希保存。
- 让现有功能统一运行在认证保护的企业后台壳层内。
- 保持数据库、API、TypeScript 类型和可访问性状态可测试、可解释。

**Non-Goals:**

- 本变更不实现用户自助注册、忘记密码邮件、多因素认证、SSO/SCIM 或跨租户切换。
- 不保留开发令牌 API、外部 subject 或自动用户映射兼容层；本地调试同样通过真实系统用户登录。
- 不复制或分发 Minimal Dashboard 的商业源码、商标、Logo 和插画资源。
- 不在本变更实现复杂 HR 流程、岗位编制、审批流或组织历史版本。

## Decisions

### 1. 本地账号替换外部身份映射

`users` 删除 `external_subject`，增加必填规范化邮箱、密码哈希、组织单元、职位、手机号和登录时间。登录成功后 JWT 的 `sub` 直接使用系统 User UUID，认证依赖按 UUID 与 tenant_id 加载 active 用户，不再创建或兼容外部身份映射。

### 2. 密码采用 scrypt 单向哈希

使用 Python 标准库 `hashlib.scrypt`、每个密码独立随机盐、常量时间比较和版本化存储格式。它避免引入新的认证依赖，也明确区分密码哈希与可逆加密。登录失败统一返回相同错误，避免枚举邮箱。

### 3. 初始管理员由启动引导服务幂等创建

数据库迁移只负责结构，不嵌入明文密码或环境专属账号。应用启动时在显式启用引导且数据库尚无用户时，根据环境变量创建默认租户、根组织和平台管理员。生产环境必须显式配置不同密码，并拒绝已知本地示例密码。

### 4. 组织采用租户内邻接表

`organization_units.parent_id` 表示父节点，配合租户、同级名称唯一约束和排序字段构建树。写操作校验父节点同租户且禁止自引用/循环；删除只允许空节点，避免级联误删用户和部门。

### 5. 管理 API 始终从 JWT 推导租户

公司、组织和用户接口不接受客户端 tenant_id。所有查询按当前租户过滤，并要求 `platform_admin`。管理员不得停用或移除自己的最后一个平台管理员角色，避免租户被永久锁死。

### 6. Web 使用短期 JWT 的本地持久化认证

登录接口返回 Bearer Token，前端保存在现有 localStorage 版本键中；认证守卫先调用 `/v1/auth/me` 验证。401 清除令牌并跳转 `/login`，退出登录同样清除。相较 Cookie 会话，此方案与现有 SSE Bearer 认证兼容；生产部署后可再升级为 BFF + HttpOnly Cookie。

### 7. 统一后台壳层采用嵌套路由

`/login` 独立渲染，业务路由统一作为受保护布局的子路由。桌面端使用约 280px 固定侧栏和顶部工具栏，移动端使用可展开导航。页面内容保持最大宽度和圆角卡片，不把前端导航隐藏当成权限控制。

## Risks / Trade-offs

- [localStorage 中 JWT 可被 XSS 读取] → 保持短有效期、无第三方脚本，并在生产上线前规划 HttpOnly Cookie/BFF。
- [默认凭据公开后可被滥用] → 仅本地默认启用，生产拒绝示例密码且要求运维注入；首次部署应立即修改。
- [邻接表读取需要应用层组树] → 首版组织规模有限，一次租户内查询后内存组树；后续可按规模升级递归 CTE。
- [停用用户的已有 JWT 尚未过期] → 每次认证依赖加载数据库用户并校验 active 状态，实现即时失效。
- [视觉高度参考商业模板] → 只复用通用布局语言，所有品牌、文案、组件代码和图形均为项目自有实现。

## Migration Plan

1. 在确认连接目标为当前项目数据库后，迁移显式清空所有现有业务表数据。
2. 迁移重建 `tenants/users` 身份字段，创建 `organization_units`，补齐表与字段注释。
3. 部署 API 后运行幂等引导，创建默认租户、根组织和管理员。
4. 发布登录与后台壳层；旧 localStorage 开发令牌使用新键隔离并自动退出。
5. 验证默认管理员登录后立即建议修改密码。
6. 因迁移主动清空历史数据，数据库结构可 downgrade，但历史数据不可恢复；执行前依赖用户已经给出的清空授权。

## Open Questions

- SSO、MFA、密码找回和强制定期轮换留待后续身份治理变更。
- 多公司集团与用户跨租户成员关系留待实际客户场景明确后设计。
