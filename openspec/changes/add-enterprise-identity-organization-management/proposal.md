## Why

当前系统依赖浏览器自动签发开发令牌，无法让企业管理员创建和停用真实用户，也没有公司资料与组织架构，无法作为企业内部技术支持 Agent 平台投入多人使用。现在需要建立可审计的本地账号认证和租户组织管理，同时把 Web 应用升级为一致的企业管理后台体验。

## What Changes

- 增加邮箱与密码登录，密码使用带随机盐的 scrypt 单向哈希保存，JWT 只在服务端验证成功后签发。
- 增加默认公司和默认平台管理员引导；本地环境由环境变量提供初始邮箱与密码，生产环境禁止使用示例密码。
- **BREAKING** 删除外部身份 subject 兼容与自动用户映射，JWT 主体直接使用系统用户 UUID。
- **BREAKING** 本次迁移清空当前项目数据库中的历史业务数据，以全新企业账号和组织模型重新初始化。
- 扩展用户资料与状态，支持管理员创建、编辑、启用、停用用户和重置密码。
- 增加公司资料和树形部门，部门业务资料仅保留名称和上级部门，支持创建、编辑和上下级关系。
- 为用户管理、组织管理和公司资料接口实施租户隔离与平台管理员授权。
- **BREAKING** Web 应用不再自动生成开发令牌，未认证访问统一跳转登录页。
- 增加与 Minimal Dashboard 视觉语言一致的登录页、固定侧栏、顶部工具栏和管理内容布局，但使用项目自有品牌、文案和图形资产。
- 增加用户管理与组织架构页面，并把现有 Agent、模型与员工工作台纳入统一后台导航。

## Capabilities

### New Capabilities

- `password-authentication`: 邮箱密码认证、会话令牌、登录错误与初始管理员安全引导。
- `tenant-user-management`: 租户内用户创建、资料编辑、状态控制、角色分配和密码重置。
- `organization-management`: 公司资料与树形组织单元的查询和管理。
- `enterprise-application-shell`: 登录保护、Minimal 风格企业后台壳层、响应式导航和身份菜单。

### Modified Capabilities

- `agent-management-console`: 现有 Agent、模型和员工工作台入口纳入登录后的企业后台导航与统一权限体验。

## Impact

- 数据库新增组织单元并重建租户、用户身份字段；后续迁移移除部门代码、类型、排序和状态字段以及冗余公司根节点，需要验证 Alembic 迁移、表注释和真实 PostgreSQL 状态。
- API 增加登录、用户、公司与组织管理端点，删除开发令牌入口并重写认证依赖。
- Web 路由增加 `/login`、认证守卫、用户和组织页面；现有业务路由被统一后台壳层包裹。
- 新增密码哈希与验证服务，不在日志、响应、审计或前端存储中暴露密码哈希。
- 测试覆盖登录、租户隔离、权限、用户生命周期、组织树、首次启动引导和前端构建。
