# Web 前端实现约定

本文件作用于 `apps/web_chat` 及其全部子目录。新增或修改页面、表单和基础组件时必须遵循以下约定，并优先复用 `src/components/ui` 中已有的 shadcn/Radix 封装。

## 技术与目录边界

- 使用 React、TypeScript、Tailwind CSS 和项目已有的 shadcn/Radix 组件，不在页面内重复实现已有基础组件。
- 页面按一级业务功能建立独立目录，页面入口固定为当前目录下的 `index.tsx`；智能体管理使用 `pages/agent-management`，企业管理使用 `pages/enterprise`，再按 `agents`、`models`、`users` 等二级业务功能建目录，不建立无明确产品语义的 `admin` 总目录，禁止继续新增 `XxxPage.tsx` 式的平铺页面文件。
- 添加、编辑、测试、重置、删除等仅属于当前页面的功能组件统一放在当前功能目录的 `components/` 下；页面 `index.tsx` 负责数据编排和路由入口，不直接堆放弹窗实现。跨页面复用的通用业务组件放在 `src/components`，基础 UI 原语放在 `src/components/ui`，路由统一放在 `src/router`。
- 页面专属组件通过明确的 props 接收数据和回调，不在组件内部重复请求页面已经持有的数据；页面目录之外不得反向依赖页面专属组件。
- 跨页面共享且需要统一刷新的服务端状态使用 Redux Toolkit，Store、Slice 和类型化 Hook 统一放在 `src/store`；页面不得为同一份全局数据维护重复的本地副本。
- API 数据必须在 `src/types.ts` 声明明确类型；新增接口字段需要逐字段添加中文 JSDoc，不使用无依据的 `any`。
- 图标统一使用 `lucide-react`；纯装饰图标隐藏于辅助技术，可点击的纯图标按钮必须提供中文 `aria-label`。

## 尺寸与圆角

- 普通 `Input` 使用 `h-10 rounded-lg`；登录等强调场景可使用 `h-14`，但圆角仍保持 `rounded-lg`。圆角使用 Tailwind 默认主题，不在项目中覆盖 `--radius-*` 映射。
- 普通 `Button` 使用组件既有尺寸和 `rounded-lg`；登录主按钮固定为 `h-12 rounded-lg`。
- 小型图标按钮使用 `size="icon"`，紧凑操作可使用 `size="sm"`，不得在页面中随意声明新的高度体系。
- 内容卡片默认使用 `rounded-2xl`，弹窗内容使用 `rounded-2xl`，菜单使用 `rounded-xl`，菜单项使用 `rounded-lg`。
- 后台页面标题统一使用 `PageHeader`：标题、描述字号、间距和右侧主操作不得在页面内另写一套；标题下方保持统一的内容间距。
- 头像保持圆形；聊天输入区域可按沉浸式会话界面的既有造型单独处理。

## 表单与校验

- 所有文本、邮箱、密码、数字和 URL 输入框都必须提供与字段语义一致的占位提示，统一使用“请输入{字段名称}”格式，例如“请输入邮箱地址”“请输入密码”；不得使用“请输入内容”等无法说明字段含义的模糊文案。占位文案不单独设置字号，跟随输入框正文尺寸，并统一使用 `font-normal` 和 `text-muted-foreground/50`，视觉层级必须弱于用户输入正文。
- 表单必须同时覆盖提交校验和字段变更校验；字段校验统一使用 `change` 模式，禁止使用 `onBlur`/失焦触发校验。用户每次输入或选择变化时都要立即按当前值重新校验并更新错误状态。
- 需要自定义错误文案的表单统一使用 `noValidate`，不得依赖浏览器原生 `required`、`minLength` 气泡；提交时由表单校验逻辑返回字段错误。
- 错误字段必须设置 `aria-invalid="true"`，并通过 `aria-describedby` 关联字段下方的错误信息。
- `Input` 的错误态统一为红色边框、红色聚焦边框和浅红色 focus ring；禁止只用颜色而不显示文字说明。
- 字段错误仅在存在错误时渲染在输入控件下方，使用 `text-xs text-red-600`；无错误时不渲染错误节点、不占用额外空间。
- 弹窗表单的字段统一使用 `src/components/FormField.tsx` 的 `FormField`，通过 `required` 参数在标题前显示红色 `*`，通过 `error` 参数在字段下方动态显示错误；提交校验失败时使用 `noValidate` 和业务校验逻辑，并通过 `aria-describedby` 关联错误节点。
- 接口或跨字段错误使用页面或表单级 `role="alert"`；成功反馈使用 `role="status"`，不得把服务端错误伪装成字段错误。
- 增删改、启停、发布、连接测试等操作结果统一调用 `src/lib/notifications.ts`，成功使用绿色 Toast、失败使用红色 Toast、需要注意的非失败结果使用黄色 Toast；页面不得为操作结果重复创建 Alert、提示条或自定义浮层。
- 页面初始化或数据加载失败、字段校验、只读/禁用原因等需要持续可见或可恢复的状态仍在内容区域就地展示，不使用会自动消失的 Toast。
- 列表中的启用、停用、正常等常规状态统一使用无边框纯色状态标签，具体颜色规则见下方 `StatusBadge` 约定。
- 列表状态标签统一使用 `src/components/StatusBadge.tsx`：必须去掉边框，使用纯色背景和高对比度文字；成功/正常使用绿色，失败/异常使用红色，进行中/待处理使用琥珀色，未知状态使用灰色。页面不得自行定义另一套状态标签颜色。
- 提交期间禁用提交按钮并显示明确的进行中文案；失败后必须恢复可操作状态。

## Button 使用规则

- `Button` 默认 `type="button"`；只有真正提交表单的按钮显式设置 `type="submit"`。
- 主操作使用 `default`，次操作使用 `outline`，弱操作使用 `ghost`，危险且不可逆操作使用 `destructive`。
- 只有两个互斥状态的配置（例如启用/停用、授予/不授予权限）统一使用 `Switch`，不要用 Select 或 Checkbox 模拟开关。
- 同一操作区域只保留一个主按钮；删除、停用等危险操作必须有明确文案，并按风险使用确认弹窗。
- 禁用状态必须同时表达不可操作原因；异步操作期间避免重复提交。

## 现有基础组件规则

## 列表页面统一标准

以下规则适用于所有后台数据列表、卡片列表、树形列表和 Analytics 列表页面，统一以“智能体管理 / Agent 管理”为视觉和交互基准：

- 页面结构固定为 `PageHeader`、列表工具栏、内容容器三层。标题和描述必须使用 `PageHeader`，标题字号、描述颜色、间距保持组件默认值；新增、创建等主操作放在 `PageHeader.actions` 右侧。
- 列表工具栏统一使用 `ListToolbar`。有查询条件时，所有筛选控件从左侧开始排列且不增加额外左内边距，右侧只放刷新按钮，不显示列表标题、统计数量或其他摘要；无查询条件时左侧显示“{功能}列表”，右侧仍只放刷新按钮。
- 列表外层容器保持扁平白底，不添加边框和阴影；圆角沿用 `rounded-2xl`，不得在页面内为同类列表增加新的容器视觉体系。
- 查询条件统一使用 shadcn `Select`、`Input` 等现有组件。查询值发生变化时立即重新请求数据并将页码重置为第 1 页；查询条件较多时允许换行，但不得把刷新按钮挤到查询控件左侧。
- 刷新操作必须复用当前列表请求，使用 `ListToolbar` 的刷新按钮；请求期间按钮禁用并显示旋转图标。初始化、刷新、筛选、搜索和翻页等所有列表请求必须严格遵循“先同步设置 Loading → 让页面渲染 Loading → 等待 300ms → 再调用接口”的顺序，统一通过 `delayRequest` 实现请求延迟；禁止先调用接口再补 Loading，也禁止把 300ms 延迟放在 Loading 状态之前。列表加载视觉统一使用 `ListLoadingOverlay`（白色半透明悬浮层 + 紧凑 `GlobalLoading`），禁止使用 Skeleton 或页面内自定义 Spinner；Dashboard 的整体指标骨架属于页面级概览加载，不属于列表，可保留既有 Skeleton。
- 数据列表统一使用 `AppTable`；列定义只使用 `title`、`dataIndex`、`key`、`render`、`align`、`width`，单元格内边距、表头背景、横向滚动和行分隔线由组件统一管理，不在业务页面覆盖固定行高。
- 列表必须明确处理加载、空数据、接口错误和无权限状态：加载显示 `ListLoadingOverlay`，空数据由 `AppTable.emptyText` 或列表专属空态展示，错误在内容区域显示可重试提示；禁止用 Toast 替代持续可见的加载错误。
- 分页统一由 `AppTable.pagination` 管理。服务端分页传入 `total` 并将当前页数据直接交给表格；客户端分页不传 `total`。分页栏左侧显示“共 X 条”且不添加左内边距，右侧依次放每页条数、页码导航和快速跳转；业务页面不得自行实现第二套分页。
- 列表状态统一使用 `src/components/StatusBadge.tsx`：无边框、纯色背景和高对比度文字。成功/正常为绿色，失败/异常为红色，运行中/待处理为琥珀色，未知状态为灰色；禁止同一状态在不同页面使用不同颜色或 Outline 样式。
- 列表响应式布局优先自然换行和横向滚动，禁止通过固定页面宽度造成整体横向滚动；操作列靠右，长文本使用截断或换行，筛选控件在窄屏下可换行。

- `Input`：单行文本、邮箱、密码、数字和 URL 输入；统一通过 `aria-invalid` 启用错误视觉。
- `Textarea`：多行内容和 Prompt 编辑；沿用既有无独立边框样式，由外层容器负责边界和焦点造型。
- `Dialog`：创建、编辑和低风险确认；必须提供 `DialogTitle` 与 `DialogDescription`。
- `AlertDialog`：删除等不可逆操作；必须清楚说明影响范围，并提供取消操作。
- 所有 `Dialog` 和 `AlertDialog` 默认禁止点击遮罩层或弹窗外部区域关闭；关闭必须通过明确的关闭、取消、确认按钮或业务完成后的受控状态变更，避免误触丢失表单内容。
- `DropdownMenu`：同一对象的次级操作集合，不承载复杂表单。
- `AppDrawer`：项目内所有业务抽屉统一使用 `src/components/AppDrawer.tsx`，禁止页面直接组合 `SheetContent`。组件采用固定头部、`min-h-0 flex-1 overflow-y-auto` 主体和固定底部；头部左侧显示标题，描述仅在有值时渲染，右侧使用关闭 X。底部默认提供“取消”和“确认”按钮，查看详情等只读场景可隐藏确认按钮，危险操作使用 `destructive`。异步操作期间禁用按钮并阻止关闭。移动端导航如需使用抽屉，也必须通过 `AppDrawer` 的 `side="left"`、`showHeader={false}` 和 `showFooter={false}` 配置。
- `AppDialog`：项目内所有业务 `Dialog` 与 `AlertDialog` 统一从 `src/components/AppDialog.tsx` 引入，禁止页面直接引用底层弹窗入口。弹窗默认最大高度为 `calc(100svh - 32px)`，上下至少保留 16px 安全间距，关闭 X 始终固定在弹窗右上角；弹窗外层只负责固定尺寸和裁剪，顶部标题区、底部操作区使用固定层，不参与主体滚动；内容超出时仅中间 `DialogBody` / `AlertDialogBody` 滚动，滚动条必须贴在弹窗内容区域最右侧，不能贯穿标题和底部操作区。表单必须按“`DialogHeader` + `DialogBody` + `DialogFooter`”三段结构组织，禁止把整个 `form` 作为滚动容器。业务弹窗不得自行设置超过可视高度的固定高度。
- `SearchableSelect`：需要从服务端选择 Agent、用户等实体时统一使用 `src/components/SearchableSelect.tsx`。首次展开默认请求并缓存第一页 20 条，可通过 `pageSize` 配置；未输入关键字时再次展开直接复用缓存，不得重复请求。从有值主动清空关键字也视为一次查询，输入变化必须立即显示 Loading，500ms 防抖只用于延迟请求；非空关键字输入同样使用 500ms 防抖，并忽略过期请求结果。进入 Loading 后再延迟 300ms 发起请求，加载视觉统一使用紧凑 `GlobalLoading`。数据加载函数统一接收 `(keywords, pageSize)`，接口查询参数统一命名为 `keywords`，不得在页面内重复实现搜索下拉。
- `ScrollArea`：仅用于内容确实可能溢出的固定区域；空白新建页不得为了布局强制出现滚动条。
- `Avatar`：用户或 Agent 身份展示；图片失败或缺失时提供稳定的文字/图标 fallback。
- `BrandLogo`：登录页和后台壳层统一使用，不再创建字母占位 Logo。
- `AppTable`：后台数据列表统一使用轻量表格封装，并按 Ant Design 风格传入 `columns`、`dataSource` 和 `rowKey`；列仅按需使用 `title`、`dataIndex`、`key`、`render`、`align` 与 `width`。空数据统一由组件在表体显示“暂无数据”，页面不得重复实现空状态，可按需通过 `emptyText` 覆盖。分页通过 `pagination` 启用，默认展示页码、每页条数选择和指定页码跳转；每页条数选项由组件内部统一维护，业务页面不得重复定义。传入服务端 `total` 时 `dataSource` 视为当前页数据，否则执行客户端切片，可按需传入受控 `current`、`pageSize`、`onChange`、`showTotal`、`showSizeChanger` 和 `showQuickJumper`。分页汇总“共 X 条”统一放在分页栏左侧，分页栏左侧不额外增加内边距。表头背景、边框、横向溢出以及单元格 `px-6 py-4` 由组件集中管理，不设置固定行高。
- `ListToolbar`：所有列表、卡片列表和树形列表统一使用 `src/components/ListToolbar.tsx`。有查询条件时查询控件全部放左侧且不额外增加左内边距，右侧只保留刷新按钮，不显示列表标题、统计数字或其他摘要；无查询条件时左侧显示“{功能}列表”标题，刷新仍在右侧。列表外层容器不添加边框或阴影。页面不得把刷新按钮放回 `PageHeader` 或列表内容标题区域，也不得为单个页面重复实现工具栏布局。
- `DepartmentTreeSelect`：新增部门、编辑上级部门、人员组织归属和列表部门筛选统一使用；组件直接读取 Redux 部门树，不接受页面透传的部门集合；选中后展示完整层级路径，业务表单或筛选条件只保存末级部门 UUID，下拉默认最多展示四级。列表筛选使用紧凑模式隐藏字段标题，不提供额外关键字搜索。
- `SelectContent`、`PopoverContent`、`DropdownMenuContent` 等 Portal 浮层必须使用不透明背景、明确边框与阴影，并保持高于 Dialog 内容的层级，禁止与后方文字或控件视觉重叠。

## 状态、响应式与可访问性

- 全局页面或路由加载统一使用 `src/components/GlobalLoading.tsx`：中心显示平台 Logo，外层使用两条不同颜色的圆角菱形线圈并以相反方向旋转；必须提供可访问的 `role="status"` 和中文加载说明。列表或局部区域加载可使用紧凑加载状态，不应遮挡整页。
- 受保护路由首次验证可使用全屏 Loading；已验证身份后的侧栏菜单切换不得重复显示全屏 Loading，避免整页闪烁。
- 管理后台页面统一挂载在 `src/layouts/MainLayout.tsx` 的嵌套路由 `Outlet` 下；页面组件不得再次包裹旧式页面壳层。登录页和 Chat 页面使用独立布局，不嵌套管理后台主布局。
- 主布局侧栏菜单项统一使用 `rounded-lg`；普通悬浮背景使用浅灰色，选中项使用浅绿色背景和绿色文字，选中项悬浮时使用更深的薄荷绿色背景（`#d5f0e8`）与绿色文字（`#008f63`）。
- 主布局菜单使用递归树结构，最多支持三级菜单；一级功能负责分组展开，当前分组使用绿色选中态，二级及末级当前项使用浅灰选中态。子菜单通过左侧竖线和圆弧折线表示层级，展开与收起必须提供平滑高度和透明度过渡，并兼容键盘操作及 `aria-expanded`。
- 主布局顶部右侧用户信息使用可访问的下拉菜单，顶部不使用边框，使用轻微底部阴影区分层级；菜单内容保持白色、圆角和退出登录操作。
- 主布局顶部栏使用 `fixed` 定位，页面内容必须预留对应顶部空间；不得使用会随内容滚动的普通流式顶部栏承载全局导航。
- 管理后台列表页的新增、编辑、设置和重置等操作优先使用 `Dialog`/`AlertDialog` 弹窗，列表区域只保留摘要、筛选和操作入口，避免表单长期占据列表布局。
- 管理后台页面的主要操作统一通过 `PageHeader` 的 `actions` 放在页面标题右侧，不得放在内容标题、页面侧栏或独立操作卡中；下方区域只承载业务内容与内容级操作，移动端允许标题和主要操作自然换行。
- 管理后台所有挂载左侧菜单的页面，顶部内容间距统一由 `MainLayout` 的主内容区提供（以“模型管理”页面为基准）；页面组件不得再为整个内容根节点叠加 `pt-*` 顶部内边距。业务区块之间的留白仅用于标题与内容分组，不得改变页面整体起始位置。聊天等独立沉浸式布局不受此规则约束。
- 页面交互控件优先使用 `src/components/ui` 中的 shadcn 组件；业务页面不得直接新增原生 `select` 或 `input[type=checkbox]`，选择器统一使用 `Select`，复选状态统一使用 `Checkbox`，移动抽屉和折叠区域分别优先使用 `Sheet` 与 `Collapsible`。
- 数据页面必须设计加载、空数据、错误、无权限和成功反馈状态，禁止使用空白页面代表状态。
- 部门管理页每次进入时必须刷新 Redux 部门树，首次刷新完成前持续显示 Loading；创建、编辑、删除部门后必须强制刷新全局部门树。部门名称路径统一调用全局路径解析方法，不在业务页面重复遍历树。
- 可交互元素需要可见焦点态并支持键盘操作；不得用无语义 `div` 代替按钮或链接。
- 登录页桌面左栏固定 `580px`，`lg` 以下完全隐藏；移动端只呈现完整可操作的登录表单。登录页桌面端与移动端的 `BrandLogo` 均固定在 `left-6 top-6`，不得在响应式断点改变品牌位置。
- 管理后台桌面采用固定分组侧栏，移动端使用抽屉导航；页面不得通过固定宽度造成横向滚动。
- 完成 UI 修改后至少运行 `pnpm --dir apps/web_chat run type-check`；涉及布局、样式或构建产物时同时运行 `pnpm --dir apps/web_chat run build`。
