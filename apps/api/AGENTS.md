# AGENTS.md — 后端 API 开发约定

本文件适用于 `apps/api` 目录。除项目全局约定外，后端接口实现还必须遵循以下规则。

## 列表接口分页

- 所有普通扁平列表 `GET` 接口必须支持服务端分页，不得先查询全量数据再在 Python 内存中切片。
- 查询参数统一使用 `page` 和 `page_size`：`page` 从 1 开始且最小为 1；`page_size` 默认 20、最小为 1、最大为 100。
- 接口必须复用 `supportops_api.pagination.pagination_params`，禁止在各路由重复定义分页边界。
- 响应统一包含 `items`、`total`、`page`、`page_size` 和 `pages`，并继承 `PaginatedListResponse`。
- 数据查询必须具备确定性排序；排序字段可能重复时，必须追加稳定唯一键作为最后排序条件，避免跨页重复或遗漏。
- `total` 必须使用与数据查询相同的租户、权限和业务过滤条件，并在应用分页前通过数据库聚合获得。
- 请求页码超过总页数时返回空 `items`，保留请求的 `page` 和准确分页元数据，不返回 404。
- 新增或修改列表接口时必须测试首页、后续页、空结果、越界页和非法分页参数。
- 完整树结构、整体替换型配置集合和 SSE/流式事件不适用普通分页；保留为非分页接口时，必须在代码或接口说明中明确其完整性语义和不分页原因。

## 接口契约

- 租户和权限过滤必须先于分页，客户端不得通过分页参数绕过可信身份边界。
- 分页响应模型、查询参数和字段说明必须同步出现在 OpenAPI、前端类型及相关 OpenSpec 规范中。
- 不保留新的 `limit/offset` 对外契约；数据库层可使用由 `page/page_size` 计算出的 offset。
